Feb 25 2026  ·  Numerical Computing  ·  Python / NumPy
Pure Python vs. NumPy — Performance Benchmarking
A rigorous performance study comparing pure Python loop-based computation against NumPy vectorized operations for element-wise vector multiplication (1-D) and true matrix multiplication (2-D). Both tasks were benchmarked at five input sizes from n=10 to n=500, with 15 timed trials each, one warm-up run, a fixed random seed, and correctness verified via np.allclose before any timing was recorded.
NumPy Vectorization Benchmarking O(n) vs O(n³) BLAS / Cache Locality Median Timing
Matrix Multiplication7,288× fasterNumPy vs. Python at 500×500 — same math, entirely different speed
Vector Multiplication33× fasterNumPy vs. Python at 500 elements — gap grows with input size
Measurement Rigor15 timed runsPer data point, with 1 warm-up run and a fixed random seed for fairness
What I Built
Implemented py_elementwise and np_elementwise — the two core 1-D vector multiplication functions. The Python version loops explicitly over paired elements at O(n); the NumPy version uses the native a*b vectorized operator. Both fed into a shared median_time benchmarking harness that handled warm-up, trial repetition, and timing isolation so all comparisons were fair across implementations.

The experiment design used five input sizes [10, 50, 100, 200, 500], applied to both 1-D and 2-D operations, yielding 20 data points in total. Each was run independently per function and recorded to a results table before any analysis began.
Results & Analysis
The 1-D speedup grew from 1.1× at n=10 to 33× at n=500 — slowly at first because fixed overhead (timer resolution, function calls) dominates small inputs. The matrix multiplication gap was far more dramatic: 7,288× at 500×500, driven by the O(n³) compounding of loop overhead vs. BLAS-backed NumPy.

The root cause is twofold: NumPy executes in compiled C/Fortran with no Python interpreter overhead per iteration, and stores data contiguously in memory, enabling CPU cache reuse. Python lists use pointer indirection, causing cache misses on every element access in a nested loop. The practical lesson: O(n) and O(n³) implementations that look equivalent in theory diverge catastrophically in wall-clock time at scale.
Takeaway A 7,000× gap for the same mathematical operation changed how I evaluate code before writing it. Big-O complexity describes growth rate, not absolute speed. Library choice, memory layout, and interpreter overhead are first-class engineering decisions.

Rational Agent Design — Comparing Reflex, Random, and Model-Based Agents
Designed and ran a controlled comparison of three agent architectures — Simple Reflex, Random, and a Model-Based DFS exploration agent — across two environments: a two-location vacuum world and a 2D grid with obstacles. Ran 50 randomized trials per agent and a constrained 1×18 corridor experiment to isolate policy differences from environment variability.
PEAS Framework Model-Based Agent DFS Exploration Fixed Horizon Evaluation Cumulative Score
Best Agent in CorridorScore: 3,279Model-based agent dominated the tight 1×18 hallway by learning blocked directions
Best Agent in Open GridScore: 2,462Simple Reflex agent won on open 2D grids — fewer wasted moves than DFS
Experiment Size50 trialsRandomized start positions and dirt each run to eliminate bias
What I Built
Designed the experimental framework for the two-location world: fixed a 20-step horizon, randomized starting position and dirt configuration at each trial, and defined cumulative score (cleaning bonus minus action cost) as the metric. Co-implemented Exercise 2.11 — the environment loop, percept generator, and transition function that all agents shared.

The three agents operated on identical state information. The Simple Reflex agent follows one rule: SUCK if dirty, else move. The Random agent samples uniformly from all actions. The Model-Based agent builds an internal map, performs DFS, and avoids retrying blocked directions.
Results & Analysis
In a single run both agents started at A with both squares dirty. The reflex agent scored 28; the random agent scored 12 — a 57% gap — because the random agent wasted moves on walls, repeated visits, and NOOPs before finally cleaning B at step 19.

Across 50 trials the gap narrowed to 34.18 vs 32.84 because when squares start clean, the reflex agent's early-cleaning advantage disappears. In the 2D grid, reflex (2462) beat model-based (2322) on average — systematic DFS cost too many steps in small open spaces. But in the 1×18 corridor, model-based dominated (3279 vs 1939) by learning UP/DOWN were blocked and never wasting moves on them again. The right agent depends entirely on the environment's geometry.
Takeaway Smarter doesn't always mean better. A model-based agent that systematically avoids wasted moves is a liability in open spaces but a decisive advantage when the environment has structure that can be learned and exploited.

Apr 22 2026  ·  Search Algorithms  ·  Python / Matplotlib
Search in the Real World — Visibility Graph Navigation & Missionaries Problem
Two classical search problems tackled back to back. Problem 3.7: navigating a continuous plane filled with polygonal obstacles by reducing the infinite space to a 35-node visibility graph, then comparing A*, Greedy BFS, and UCS head to head. Problem 3.9: modeling the Missionaries and Cannibals river-crossing puzzle as a 20-state finite graph and finding the optimal 11-step solution with BFS.
A* Search Visibility Graph UCS · Greedy BFS Breadth-First Search Admissible Heuristics State Space Design
Shortest Path FoundCost: 13.342A* and UCS both confirmed this as optimal; Greedy found 13.488 (suboptimal)
A* Efficiency14 vs 31 nodesA* expanded 14 nodes to find the answer; UCS needed 31 — same result, 2× the work
River Crossing Puzzle11 crossingsBFS found the minimum moves to safely cross all missionaries and cannibals
What I Built
Wrote the complete Methodology section and led the analysis for Problem 3.7. The key implementation insight: a 2D plane with infinite states was reduced to a finite 35-node graph by exploiting the fact that optimal paths can only bend at polygon vertices. The visibility graph was constructed by testing every pair of nodes for mutual visibility — an edge was added only if the connecting segment did not penetrate any obstacle interior (verified by sampling three interior points per candidate edge), yielding 111 valid edges.

Three best-first search variants shared a min-heap priority queue: A* with Euclidean distance heuristic f(n)=g(n)+h(n), Greedy BFS with f(n)=h(n) only, and UCS with f(n)=g(n) only.
Results & Analysis
A* and UCS both found the optimal cost of 13.342. That UCS matched A* exactly confirms the Euclidean heuristic is admissible — it never overestimates. Greedy reached a path costing 13.488 in just 3 node expansions, rushing toward the goal without tracking accumulated cost. A* needed 14 expansions; UCS needed 31.

The 2.2× efficiency gain of A* over UCS came entirely from heuristic guidance — the same optimal answer, half the work. For Problem 3.9, BFS explored the 20-state graph level by level and returned the optimal 11-crossing solution. A visited set was mandatory because the graph contains cycles (moving a person across and back returns to a prior state), and without it the search loops indefinitely.
Takeaway Reducing an infinite plane to 35 nodes before running any search was the decisive step — not which algorithm we chose. The best algorithm on a poorly formulated problem loses to a mediocre algorithm on a well-formulated one. Representation first, algorithm second.

Apr 28 2026  ·  Local Search  ·  Python / UC Berkeley AIMA
Local Search Showdown — Hill Climbing, Random Restart & Simulated Annealing
A 400-run experiment comparing four local search algorithms — steepest-ascent hill climbing (SAHC), first-choice hill climbing (FCHC), random-restart hill climbing (RRHC), and simulated annealing (SA) — on two benchmark problems with different landscape structures: the 8-queens problem (complex, many local optima) and the 8-puzzle (simpler, directed). Each algorithm ran 50 independent trials per problem, measuring both success rate and average search cost.
Hill Climbing (3 variants) Simulated Annealing 8-Queens · 8-Puzzle Success Rate Search Cost Manhattan Distance Heuristic
Most Reliable Algorithm100% solvedRandom-Restart Hill Climbing solved every single trial on both problems
Simulated Annealing86% → 16%86% success on complex 8-queens, but only 16% on simpler 8-puzzle — landscape matters
Total Experiments400 runs4 algorithms × 2 problems × 50 trials each for statistically reliable results
What I Built
Designed the full experimental protocol and wrote the Methodology and Results sections. The 8-queens problem was modeled as a complete-state formulation: a tuple of 8 queen row positions, with negative attacking-pairs as the value function (maximum = 0 conflicts = solution). The 8-puzzle used negative Manhattan distance to the goal as its value function. All four algorithms were built on top of the UC Berkeley AIMA Python repository.

Randomized instances were generated carefully: 8-queens via random row assignments per column; 8-puzzle via 20 random legal moves from the goal state (guaranteeing solvability). Both metric types — percentage solved and average search cost (total candidate states evaluated) — were recorded per run, then aggregated per algorithm-problem pair into the master summary table.
Results & Analysis
The starkest result: Simulated Annealing solved 86% of 8-queens instances but only 16% of 8-puzzle — a 70-point swing from the same algorithm on different problems. SA's temperature schedule allows it to escape local optima by occasionally accepting worse moves, which is exactly what the highly rugged 8-queens landscape needs. On 8-puzzle, that same randomness is expensive overhead when the landscape is smoother and directed search works fine.

RRHC was the only algorithm to hit 100% on both problems, at the cost of higher total evaluations (cumulative across restarts). SAHC solved 68% of 8-puzzle cheaply (avg 13 evaluations) but only 20% of 8-queens — a classic local-optima trap. FCHC evaluated fewer states per step but got stuck just as often. The key lesson: no algorithm wins universally; every choice is a landscape-specific tradeoff.
Takeaway Running 400 experiments made the algorithm-landscape interaction visceral. SA going from 86% to 16% on a different problem isn't a quirk — it's the central truth of local search. Choosing an algorithm without knowing the landscape structure is guessing.

May 8 2026  ·  Constraint Satisfaction  ·  Analytical Report
CSP Simplified — Three Ways to Model Einstein's Riddle
An analytical deep-dive into Constraint Satisfaction Problems using the Einstein Zebra Puzzle as the test case. The same puzzle was modeled three ways — Position-Based, House-Based, and Permutation/Boolean — and each representation was evaluated for computational efficiency, human readability, heuristic compatibility (MRV/LCV), and compatibility with industrial solvers (SAT, ILP). The goal: understand how representation choice drives solver performance, not just correctness.
CSP Formulation Constraint Propagation MRV · LCV Heuristics SAT / ILP Compatibility Backtracking ALLDiff Constraints
Approaches Compared3 encodingsPosition-based, House-based, and Boolean — same puzzle, three completely different models
Boolean Model Scale125 variables5 houses × 5 attributes × 5 values — powerful for solvers, unreadable for humans
Puzzle Complexity15 clues15 logical constraints that together uniquely determine one solution out of millions
The Three Representations
Position-Based: Each attribute (color, nationality, drink, candy, pet) is a variable over house positions 1–5. Clues become arithmetic — "green is immediately right of ivory" → Green = Ivory + 1. ALLDiff constraints prevent duplicate assignments. Clean, compatible with MRV/LCV heuristics, readable. Identified as the most balanced overall.

House-Based: Each house is an explicit tuple of attributes. Constraints are logical implications — "if yellow, then Kit Kat." Mirrors how humans reason with a 5×5 grid. Heavy on logical disjunctions but excellent for visualization and step-by-step explanation.

Permutation/Boolean: 125 binary variables (5 houses × 5 attributes × 5 values). Every possible assignment is a yes/no question. Maps directly to SAT and ILP solvers (Google OR-Tools, Z3). Computationally powerful, scales to real optimization problems, but completely opaque to human inspection.
Analysis & Conclusion
Each representation captures the same problem through a different lens, with a distinct position on the efficiency-explainability tradeoff:

The position model wins for balanced use — it's compact, supports algorithmic heuristics, and stays readable. It's the right choice for most solver implementations. The house model wins on pedagogical clarity — ideal for explaining reasoning step by step and for problems where human verification matters. The boolean model wins on raw power — it scales to industrial CSP problems (scheduling, circuit layout, resource allocation) where the solver, not the human, needs to understand the structure.

The deeper insight: a logic puzzle that looks trivial encodes the same mathematical structure as university timetabling and chip design. Representation isn't a cosmetic choice — it determines what algorithms can even be applied.
Takeaway The boolean model was the hardest to read and the most powerful computationally — while the house model I initially dismissed as "too informal" was the one we kept returning to when explaining reasoning to each other. That tension between efficiency and explainability is a real engineering problem, not a textbook one.

May 18 2026  ·  Adversarial Search  ·  Python / PettingZoo
Briscas AI — Building a Card Game Agent Under Hidden Information
Implemented a full two-player AI agent for Briscas, a Spanish trick-taking card game, using the Averaging over Clairvoyance (AoC) method: sample 15 plausible opponent hands from the unknown cards, evaluate each via depth-4 minimax with alpha-beta pruning, and select the action with the highest average expected score. The game environment was built with PettingZoo's AEC (Agent-Environment Cycle) framework and evaluated across 150 total games against two opponents.
Minimax · Alpha-Beta Pruning Monte Carlo / AoC Sampling Partial Observability PettingZoo AECEnv Confidence Intervals Win Rate Analysis
vs. Random AgentWon 92%46 wins out of 50 games — AI clearly outperforms unstructured play
vs. Rule-Based AgentWon 58%Beating a smart opponent 58% of the time shows genuine strategic reasoning
Winning Margin+31.2 pts avgAverage score lead against random — not just winning, but winning decisively
What I Built
Designed the complete evaluation protocol and wrote the Methodology and Results sections. The matchup design swapped agent positions at game 25 of each 50-game set to control for first-move advantage — a standard technique in game AI evaluation that prevents position bias from masking true performance differences.

Three agents were tested: RandomAgent (uniform action sampling, baseline), HeuristicAgent (play low non-trump when leading; use minimum winning card on contested tricks), and AoCAgent (sample 15 opponent hands from unknown cards → depth-4 alpha-beta minimax on each → pick the action with highest average score). Performance was reported with 95% Wilson confidence intervals, average score margin, and standard deviation across all 50 games per matchup.
Results & Analysis
The AoC agent achieved a 92% win rate against Random (CI [80.7%, 97.3%], avg margin +31.2 points, σ=19.4). The fully-above-50% CI confirms this isn't luck — the agent genuinely outperforms unstructured play. The low standard deviation indicates stable performance across different card distributions.

Against the Heuristic, the win rate was 58% (CI [44.4%, 70.6%], avg +7.4 pts, σ=24.1). The CI touches 50%, reflecting the honest limits of a 50-game sample — and that the heuristic is a real opponent. AoC's edge appears mainly in mid-game positions where rigid rules fail: it samples possible opponent hands and identifies plays that the heuristic's fixed logic would miss. Performance stabilized at 10–15 sampled determinizations, a practical balance between decision quality and runtime for a 40-card game.
Takeaway Building an agent that plays a real card game under genuine hidden information was the hardest and most satisfying project of the semester. The 58% win rate against the heuristic — not a blowout, but consistently above chance — showed the agent was doing real strategic reasoning, not just outperforming a weak baseline.
